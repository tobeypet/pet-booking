# 毛孩預約系統

## 一句話簡介
一個免費、不用架 server 的寵物美容/洗澡線上預約系統，客人自己上網選時段預約，店家在另一個網頁後台控制哪些日子有空，資料自動存進 Google 試算表、預約自動排進 Google 日曆。

## 這是什麼、解決什麼問題

**原本的痛**
店家原本用電話、LINE 一筆一筆手動記客人的預約，還要另外抄進行事曆，忙起來容易漏抄、記錯時間，甚至兩隻毛孩被排到同一個時段撞期。客人的基本資料（過敏史、個性、體重）也沒地方好好留存，每次都要重新問一次。

**為什麼做這個**
所以做一個線上預約系統：客人自己選服務、選時間，系統會依服務類型（美容/洗澡、貓/狗、長短毛）自動算出要多久，只顯示店家真的有空的時段，不會約錯或撞期。同時把客人跟毛孩的資料統一存起來，老客人再來預約系統會自動辨識、更新最新資訊，不用每次重問一遍。

## 怎麼用（含要準備什麼）

需要準備：
- 一個 Google 帳號（放試算表 + Apps Script + 日曆）
- 一個 GitHub 帳號（免費架設網頁，不用自己買主機）
- 不需要安裝任何程式、不用付費

**給客人的網址**：`index.html` 部署後的網址，直接發給客人用手機打開就能預約。
**給店家自己用的網址**：`admin.html`，不要公開，拿來設定公休日、延長營業、台中服務日、個別時段。

第一次設定的完整流程（建立試算表 → 貼 Apps Script 程式碼 → 部署成網頁應用程式 → 把網址貼進兩個 html 檔案 → 上傳 GitHub 開 Pages）寫在下面「設定與金鑰怎麼準備」。

## 架構與檔案說明

```
index.html   → 客人端。四步驟預約流程（填資料 → 選服務 → 選時段 → 確認送出）
admin.html   → 店家後台。管理公休日/延長營業/台中服務日/個別時段
Apps Script  → 不在這個 repo 裡，寫在 Google 試算表的「擴充功能」裡
             負責：讀寫 Google 試算表、建立 Google 日曆事件
```

兩個網頁都是單一 HTML 檔（HTML+CSS+JS 全部包在一起），故意不拆檔案、不用框架，方便直接丟進 GitHub Pages 就能跑，不用任何建置（build）流程。

**資料怎麼流動：**
客人在 `index.html` 填資料送出 → 呼叫 Apps Script 網址（POST）→ 寫進 Google 試算表（客人資料 + 預約記錄兩個分頁）→ 同時在 Google 日曆建立一筆事件。
店家在 `admin.html` 設定可預約狀態 → 呼叫同一個 Apps Script 網址（POST action=saveSettings）→ 存進「後台設定」分頁 → `index.html` 每次進到選時段那步都會重新讀一次（GET action=getSettings），所以後台一改，客人馬上看得到最新狀態。

## 用了哪些技術以及為什麼選它

- **純 HTML/CSS/JS，沒用框架**：App 不大，用框架（React 之類）反而要多一層建置流程（npm install、build），對非工程背景的人來說維護起來更麻煩，單一檔案直接丟上 GitHub 就能跑。
- **Google Apps Script + Google 試算表當後端，而不是自己架資料庫/伺服器**：不用錢、不用維運（不用擔心 server 掛掉），店家本來就會看 Google 試算表，不用另外學一套後台系統。而且天生能接 Google 日曆，美容師手機上的日曆會自動多出新預約，不用手動抄。
- **GitHub Pages 放網頁**：免費、穩定、不用買主機，檔案傳上去就有網址可以用。

## 中途踩過的坑

- 一開始客人端跟後台是**同一個網頁**，用切換按鈕在「預約畫面」跟「後台管理」之間切換。後來發現客人有機會不小心點進後台，不安全，所以拆成 `index.html`（純客人）跟 `admin.html`（純店家）兩個完全獨立的檔案。
- 後台設定（公休日、延長營業等）一開始只存在瀏覽器記憶體裡，重新整理就消失，而且店家手機跟客人手機完全不會同步。後來把這些設定也寫進 Google 試算表，店家設定完自動同步，客人端每次選時段前都重新抓一次最新狀態。
- 「聯絡方式」一開始做成電話/LINE **二選一**的切換鈕，後來發現這樣會漏掉另一種聯絡方式，改成兩個欄位都顯示、電話必填、LINE 選填。
- 客人資料一開始跟每次的預約記錄混在同一個分頁，同一位客人來三次資料就重複三行，很難一眼看出「這人是誰、來過幾次」。後來拆成「客人資料」（每人一筆，自動更新、累計來店次數）跟「預約記錄」（每次新增一行，用電話對照回客人資料）兩個分頁。
- 部署 Apps Script 後一度測不出網址是否正常（顯示 404），後來確認是測試工具跟 Google 的轉址機制兜不起來，不是部署本身有問題——之後遇到「網址打不開」，先直接用瀏覽器本人打開確認比較準。

## 設定與金鑰怎麼準備（不要寫真的金鑰）

這個專案不需要任何 API Key 或密碼，Google Apps Script 部署成「網頁應用程式」後會給一組專屬網址，存取權限是靠部署設定管控，不是靠金鑰。

要準備：
1. 一個 Google 試算表（Apps Script 第一次執行時會自動建立以下分頁，不用手動建）：
   - 客人資料
   - 預約記錄
   - 後台設定
   - 後台日曆總覽
2. 在該試算表「擴充功能 → Apps Script」貼上專案的 Code.gs 程式碼
3. 部署 → 新增部署作業 → 類型選「網頁應用程式」→ 存取權限選「任何人」→ 部署，拿到類似
   `https://script.google.com/macros/s/xxxxxxxxxxxx/exec` 的網址
4. 把這個網址貼進 `index.html` 和 `admin.html` 開頭的 `GOOGLE_SCRIPT_URL` 常數（兩個檔案貼一樣的網址）
5. 上傳兩個 html 檔到 GitHub，開啟 GitHub Pages，完成

⚠️ 這個網址雖然不是「密碼」，但等於是系統的存取入口，不要隨便公開分享在無關的地方。

## 已知限制

- 寵物照片目前只在客人瀏覽器裡預覽，不會真的存到雲端，店家後台看不到照片（照片檔案太大，直接塞進試算表格子容易超過大小限制）。要留存照片需另外接 Google Drive。
- `admin.html` 沒有登入/密碼保護，只是網址沒公開分享，任何人知道網址就能進去改設定，安全性等同「沒鎖門但別人不知道地址」，不是真正的權限控管。
- 沒處理「兩人同時搶同一個時段」的狀況（race condition）——極短時間內兩人同時預約同一空檔，理論上有機會兩筆都成功，造成撞期。目前流量小機率極低，但沒有徹底解決。
- 後台設定是整包存成一個 JSON 字串塞進一個儲存格，不是「一列一筆」的表格結構，沒辦法直接在試算表用篩選/排序查詢，只能透過後台網頁看。
- 目前只支援單一店家、單一時區（台灣），沒有多店家、多美容師分開排班的功能。
- 沒有自動化測試，任何修改都要手動照流程跑一次確認沒壞掉。
